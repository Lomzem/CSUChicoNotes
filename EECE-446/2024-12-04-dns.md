# DNS
- Application layer protocol
- Runs _over_ transport layer: UDP
- Port 53

Mapping system from
```json
{ name: resource }
```
- IP Address is most common **resource**

`com`: is a **DNS Domain**
`google`: is a **DNS Domain**
`www`: is a **DNS Domain**

# DNS Namespace
Example:
- `www.google.com.`

Pay Registrar to get name

# Hierarchical (Tree)
Trailing `.` represents _tree root_

## Top Level Domains (TLD)
Level in tree under root
Examples: `.com`, `.edu`, `.io`

**Zone**: Subtrees in DNS Tree
    - Could include `google`, `www`, ...
Each **zone** has an **Authoritative Server**
    - Authoritative **name** servers

# DNS Resources
- Stored in name servers
- Resources provided based on query to name server

## Resource Record
How DNS structures the resources being provided
- Server receives query request with name
- Server responds with resource record of that name

### Resource Record Types
- A: IPv4 Address (most common)
- AAAA: IPv6 Address
- MX: Mail
- CNAME: Alias (Pointer to another name)
- NS: Authoritative Name Server (of name)

# DNS Query Process (Typical)
1. You send all of your queries to a single place: **Local Name Server**
    - ISP is usually Local Name Server
    - Local Name Server is provided by DHCP

2. Local Name Server does everything for you
    - You don't perform an iterative query (only send one)
    - Instead, it's usually a **recursive query**: Other server does everything for you
       - Root doesn't allow recursive queries

3. Local Name Server sends query to best Name Server it knows of
    - Retries with different Name Server if fails

4. Name Server responds back to Local Name Server with resource

5. Local Name Server sends You back response

Local Name Server useful because it could provide shared cache
